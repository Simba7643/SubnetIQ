# Requirements and implementation matrix

This matrix compares the delivered repository with the attached brief, `Pasted text(20261004-121754).txt`, and the subsequent instruction to finish phases 0–11 continuously and deliver ZIP archives. Paths are relative to the repository root. The original research report is preserved in [phase-00-research.pdf](phases/phase-00-research.pdf).

**Implemented** means the feature and its supporting source are present. It does not claim that an external service was provisioned or that every operational test has run. **Credential gated** means the implementation requires the operator's account, credentials, or provider settings for its live behavior. **Verification gap** identifies a check that cannot be inferred from source or simulated tests. **Release configuration** identifies an operator decision required before publishing. The exact executed commands and their outcomes are recorded in [verification.md](verification.md); [testing.md](testing.md) documents the repeatable gates.

### Content completeness gates

The shipped content is original explanatory material, with primary references for technical claims. The validator enforces at least 220 glossary entries, twelve specifically named courses, 300 words and two objectives per course, at least three substantive course sections, and 5,000 words across the course collection. The current collection has **5,060 words**, approximately 422 per course on average. This is a concise structured course collection, not a claim to replace a full certification textbook.

The validator also requires at least five articles of 600 words each with structured sections and primary links, at least 160 complete quiz questions covering all four difficulties, and an independently checked answer criterion for every question. It checks all sixteen JSON datasets, IDs, reference formats, dates, cross-links, network-template arithmetic, registry flags/alignment, and required source/release files. These gates prevent a future edit from replacing implemented content with empty cards or unreviewed question answers.

### Explicit operational limits

The source implementation covers the requested feature groups. The remaining boundaries are operational or verification requirements, and are not silently labeled complete live integrations:

1. Configure the intended Supabase project, migrations, authentication providers, redirect URLs, mail delivery, and storage. Then run the hosted two-account ownership, sharing, export/deletion, OAuth, and Storage checks in the deployment/test guides.
2. Configure OpenAI credentials and the chosen model to exercise the live adapter. Anthropic/Gemini adapters remain clearly labeled stubs, as permitted by the brief. Activating those providers requires implementing their live protocol adapters.
3. Verify real resolver/registry traffic, optional WHOIS access, timeouts, quota persistence, and external availability from the deployed API environment. Controlled test responses validate local behavior without asserting upstream availability.
4. Run Docker/Nginx and the committed container CI job on a capable runner if the release workspace cannot execute them. A parsed configuration is not a successful container build.
5. Set the final site/API origins and consented analytics configuration, review legal/operator details, and verify hostname/branding availability. SubnetIQ remains the user-provided working product name; source delivery does not establish trademark or domain clearance.
6. Consult `docs/verification.md` for actual accessibility, browser, performance, and test outcomes. Any unexecuted Lighthouse, assistive-technology, native Supabase, live-provider, or hosted deployment check remains a verification gap rather than an assumed pass.

The original phase-by-phase approval instruction was explicitly replaced by the later request to finish continuously. Publishing, buying hosting, creating provider accounts, supplying third-party credentials, and enabling billing are not prerequisites for delivering the complete source and phase archives.
