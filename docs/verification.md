All twenty calculator landing pages contain an actual engine-produced worked example before JavaScript runs. Full article, lesson, and glossary content is present in generated HTML.

The validated source contains **302 glossary entries**, **12 courses with 5,060 words**, **185 independently checked curated quiz answers**, **five complete technical articles**, and **four allocation templates**. Generated public pages contain more than 30,000 readable words in total.

The final Workbox generation runs after static HTML creation. Its public HTML revisions were compared with the actual generated bytes; private routes and API responses are excluded from offline caching. Bundled PDF fonts are included in the precache. These artifact checks verify the generated configuration and hashes, not real browser cache execution.

The registered `@rollup/plugin-terser` patch makes the production build work when a restricted host reports zero CPU entries. It retains minification and is included in the lockfile, workspace registration, Docker installation stages, and both source archives. In this workspace, a writable `TMPDIR` was supplied for the build. Ordinary environments may use their normal temporary directory.

Vite reports large deferred chunks for heavy optional functionality. That warning does not fail the build, but load performance still needs browser measurement. Set `VITE_SITE_URL` to the final HTTPS origin before publishing; the unconfigured build uses `http://localhost:5173`.

## Browser checks: blocked before page creation

The browser suites were discovered successfully: **50 development cases** and **51 production cases**, across desktop/mobile projects. Typechecking and linting passed. **Zero page assertions executed successfully in this workspace.**

The Playwright Chromium download returned an invalid archive. The available cloud browser rejected local preview access with `ERR_BLOCKED_BY_CLIENT`. Further address or policy bypass attempts were not made.

The sanitized local launch evidence is in [browser-launch.json](verification/browser-launch.json). No Playwright workflow, axe scan, screenshot review, service-worker offline test, PDF visual review, assistive-technology result, or Lighthouse score is claimed as passed. ## Service integration boundaries

Local calculators, reference content, learning, guest practice, local toolkit functions, and the clearly labeled assistant demonstration are available without account credentials. Live account/project/history behavior requires Supabase configuration and migrations. OAuth and email flows additionally require provider and mail settings. The implemented OpenAI adapter requires a server-side key, an accessible model, and an authenticated session; its live endpoint was not called here. Anthropic and Gemini report unavailable, as explicitly allowed by the original brief.

Actual DNS/RDAP/WHOIS availability, live TLS/header lookup behavior, hosted quota persistence, signed Storage URLs, OAuth, mail delivery, and model billing/access must be checked from the deployed environment. Controlled tests exercise their local protocol and error handling without asserting upstream availability.

No hosting account, domain, billing configuration, or live deployment was created. Deployment files and exact operator checks are supplied in [deployment.md](deployment.md), [environment.md](environment.md), and [the database guide](../supabase/README.md).

## Source and archive integrity

A syntax-aware audit inspected **143 selected TypeScript/JavaScript files** with no parse errors and no actual source comments. Another **54 code/configuration files** were checked with the corresponding Python, SQL, CSS, markup, or configuration rules. URLs, regular expressions, literal text, third-party licenses, and unchanged third-party patch context were distinguished from authored code comments. No unfinished implementation markers were found in the selected source or the **38 content/data files**; explicit unavailable-provider responses and their tests are intentional behavior.

The release packager includes environment examples, source, tests, datasets, assets, SQL, the registered dependency patch, all phase guides, and the original Phase 0 research PDF. It excludes actual environment files, private keys, installed dependencies, generated builds, browser downloads, logs, caches, raw traces, and Git internals.

Each archive contains a manifest with a SHA-256 value for every original source file. Every original file occurs exactly once in the phase archive, and its reconstruction helper verifies the bytes before writing a complete project. `release/SHA256SUMS` records the two final ZIP hashes. The source archive is the direct installable project; the phase archive supplies the same implementation organized for review.
